1. Document Scope & Product Summary

ZenK Impact is an education-sponsorship platform: sponsor circles fund underprivileged students through school partners, with vendors for supplies, mentors for uplift, parents/guardians for family linkage, and corporates for CSR. Impact is measured with ZenQ (circle engagement) and ZQA (academic quality). Kia is the platform AI guide. Legal entity referenced in legal terms: Zenk Impact India Private Limited.

FR-SCOPE-01

System boundary

This backend (ZENK BE) exposes a FastAPI REST/WebSocket API consumed by Vercel-hosted frontends. It persists data in Neon PostgreSQL (schema ZENK) and integrates ICICI, Cloudinary, SMTP, Gemini, and Groq.

FR-ROLE-02

Parent / guardian model

Parent is not a separate Persona. Parents SHALL be represented as sponsor_member with MemberKind.parent_guardian, served by the /parent microservice and family-hat switching on auth.

enums.py · student_family.py · microservices/parent/
FR-ROLE-03

Public signup endpoints

The system SHALL expose public signup for:

  • POST /signup/sponsor
  • POST /signup/sponsor_leader
  • POST /signup/sponsor_member (optional parent/guardian flag)
  • POST /signup/vendor
  • POST /signup/school
  • POST /signup/student (also creates linked parent/guardian member)
app/api/routers/signup.py
FR-ROLE-04

KYC lifecycle

Every signup SHALL carry a KYC status of pending, approved, rejected, or info_required. Admin SHALL decide via POST /admin/kyc/{signup_id}/decision. Chat token issuance REQUIRES approved KYC.

enums.py · admin_kyc.py · auth.py
FR-ROLE-05

DPDPA-aligned student login tiers

  • Under 15: guardian_only
  • 15–17: consent_required
  • 18+: independent
LoginAccessTier in enums.py · student_family.py
FR-ROLE-06

Family hats

Users with multiple linked identities SHALL list hats via GET /auth/family-hats and switch via POST /auth/switch-hat. Switching to parent SHALL require password re-entry.

app/api/routers/auth.py
FR-ROLE-07

Platform admin

Platform admin is separate from Persona. Admin SHALL authenticate via POST /auth/admin/login (cookie session) and optionally via ZENK_ADMIN_API_KEY for server-to-server calls.

auth.py · admin_deps.py · settings.py

4. Kia AI Requirements

From the Kia Constitution embedded in app/services/kia.py.

FR-KIA-01

Single engine, five voices

Kia SHALL run one knowledge base and privacy rule set across personas: KiaAryanZenNovaPriya — only personality and tone change.

FR-KIA-02

Mission & response style

  • Guide users toward measured, transparent sponsorship impact
  • Encourage and empathize; keep answers concise
  • Ground advice in supplied context data; never invent students or metrics
  • Put suggestions on a new line: {persona} suggests: …
  • Refuse legal / medical / financial advice; stay firm if user is disrespectful
  • Plain text only (no markdown / bullet formatting in model output)
FR-KIA-03

Privacy walls (hard requirements)

  • MAY share circle-level data (ZenQ, budget totals, spend)
  • Sponsored students: masked/pseudonym names only — never real name, school, address, or family details
  • NEVER share other members’ individual contributions (except circle leader when leader access is granted)
  • NEVER disclose ZenQ weights, formula, component breakdowns, or recalibration schedule
  • NEVER rank individual members against each other
  • NEVER facilitate direct sponsor↔student contact (route via school/NGO only)
FR-KIA-04

Channels & surfaces

Kia SHALL support CIRCLE_CHAT (short; no individual finance), DASHBOARD_CHAT, and PROACTIVE_TRIGGER / event briefings. Persona-specific services cover school, student, mentor, corporate, and admin dashboards.

kia.py · kia_*.py · kia_event_briefings.py

5. ZenQ & ZQA Scoring Requirements

Deterministic algorithms in app/algorithms/zenq/.

FR-ZENQ-01

ZenQ components

  • ZEQ (effort quality): weighted T (time), A (target), S (streak), Cm (communication), In (inspire), E (equity), C (commitment)
  • RAS attenuates components by attention-quality bands
  • ZCQ (context/need): need band × attendance factor × group-size factor
  • SPD from ZQA baseline → current (clamped)
  • ZIQ = base impact × ZEQ × ZCQ × SPD (per-member via effective n)
  • Inactivity decay after 2 months; weight recalibration with max shift per cycle
algorithms/zenq/core.py · constants.py · recalibration.py
FR-ZQA-01

School ZQA composite (holistic)

  • Pillars: Academic 50%, Bloom’s taxonomy 25%, SEL 25%
  • Academic subjects: English / Maths / Science / History (Social|Hindi); minimum 2 subjects to publish; single-subject cap 60
  • Bloom’s six levels (0–5); SEL five dimensions (0–5)
  • Attendance integrity: below 92% reduces score
  • Bands: Beginning / Emerging / Developing / Insightful
  • Publish blockers: complete Bloom’s+SEL, ≥2 academics, rank, class size, narrative — schools never enter ZQA manually
  • School “Estimated ZenQ uplift” is informational and MUST NOT be treated as live circle ZenQ
algorithms/zenq/zqa.py · zqa_policy.py

6. Security, Privacy & Compliance

NFR-SEC-01

JWT authentication

Access tokens default 15 minutes; refresh tokens 7 days (HS256). Server SHALL refuse to start if SECRET_KEY is missing or an insecure default.

jwt_auth.py · main.py
NFR-SEC-02

HttpOnly session cookies

Cookies zenk_access / zenk_refresh; Secure + SameSite=None when on Railway/HTTPS so Vercel FE can authenticate cross-origin. Bearer tokens remain accepted.

auth_cookies.py
NFR-SEC-03

KYC document handling

KYC docs REQUIRED at signup; stored via Cloudinary; admin review; user resubmit path under /auth.

NFR-SEC-04

Legal acceptance

Platform terms, privacy policy, parent-member terms, and student declaration SHALL be served and accepted / re-accepted through legal routes.

legal.py · terms&conditions/ · static/legal/
NFR-SEC-05

Parental consent

Admin MAY record parental consent for students; chat/WS and student Kia respect DPDPA guardian rules.

NFR-SEC-06

Student pseudonyms

Pseudonyms SHALL be 8–24 characters, exclude real-name tokens and reserved names, and be unique.

student_pseudonym.py
NFR-SEC-07

Shield content moderation

Circle chat SHALL pass Shield layers: (1) regex for PII/toxicity/self-harm/substances/geopolitics/off-platform, (2) Gemini assist, (3) fallback — before publish.

shield.py · chat/router_client.py
NFR-SEC-08

Security headers

Responses SHALL include CSP, X-Frame-Options DENY, HSTS on HTTPS, and a restrictive Permissions-Policy.

security_headers.py

8. Non-Functional Requirements

NFR-RL-01

Rate limiting

  • Global SlowAPI default: 200 requests/minute
  • Login / token: 5/min · Admin login: 10/min · Refresh/logout: 30/min
  • WS token: 60/min · Switch-hat: 10/min · Admin overview: 30/min
rate_limit.py · auth routers
NFR-DOCS-01

API documentation exposure

OpenAPI / Swagger / ReDoc SHALL be disabled by default on Railway or when frontend is HTTPS; enable only with ENABLE_API_DOCS=true.

NFR-CORS-01

CORS policy

Allow known Vercel hosts + localhost Vite ports; credentials enabled; methods GET/POST/PUT/DELETE/PATCH/OPTIONS; headers include Authorization, Content-Type, Accept, X-Zenk-Admin-Key. Extra origins via CORS_EXTRA_ORIGINS.

main.py
NFR-DEP-01

Deployment topology

API intended for Railway; frontends on Vercel; database on Neon (asyncpg pool + keepalive). Health check: GET /health → {"status":"ok"}.

NFR-DATA-01

Data store

System of record is PostgreSQL (Neon) under schema ZENK, accessed via SQLAlchemy 2 async sessions.

10. Explicit Gaps / Non-Requirements

These are observed in code and MUST NOT be treated as delivered requirements.

GAP-01

No public corporate / mentor signup routes

Persona includes corporate and mentor, and dashboards exist, but signup.py does not expose /signup/corporate or /signup/mentor.

GAP-02

Parent is not a Persona enum value

Parent capability is delivered via MemberKind.parent_guardian + /parent portal, not a first-class Persona.parent.

GAP-03

Not in this backend

Razorpay/escrow, Celery/Redis queues, Kong/Envoy, SendGrid/Twilio/FCM, TensorFlow/PyTorch training, MongoDB/Pinecone/BigQuery — present only in older aspirational docs, not as implemented requirements here.
